# 2026-11-16 部品の切り出し（MX Stage → @mxstage/eam-connectors）

運営者の判断（2026-11-16）で、業務システム（Maximo、のちに IFS・SAP）との連携の部品を MX Stage と MOYAI が共有する。
今日は MX Stage 0.2.10 から部品を切り出し、MX Stage を部品を読む形（0.3.0）に差し替えた。

## やったこと

### 部品（このリポジトリ）

- 初めの形: package.json（ESM・exports 5 つ・`prepare` で build）、tsconfig（`.ts` の import を `rewriteRelativeImportExtensions` で `.js` に出す）、
  vitest、CI（Node 20・22 で typecheck・build・test・出口の確かめ・`npm pack --dry-run`）、README（英語）、LICENSE。
- LICENSE: MX Stage の LICENSE と同じ追加の許諾・Change Date・Change License。Licensed Work だけを
  `@mxstage/eam-connectors 0.1.0 or later. The Licensed Work is (c) 2026 TSUNAGI.` にした。
  MX Stage の文にある「THIRD_PARTY_NOTICES.md に挙げた第三者の物を除く」は、部品に第三者の物が無いので外した（確かめてほしい点）。
- 移したモジュールと出口は README の「Where the code came from」の表のとおり。手を入れたのは:
  - `maximo/valueList`: `ConnectionProvider` を部品に置いた（利用側の接続の型で絞れる generic）。
  - `commit/reload`: store の `Sheet` の代わりに `ReloadableSheet`（meta・records・group）を受ける。`ParentReplacement` も部品に置いた。
  - `commit/plan`: controller から `attemptPlan`・`batchSizeOf`・`describePlanError` をそのまま移した。
  - `license/client`: localStorage は前から外から渡す形。加えて、申告を覚えるキー・橋渡しの入口・常にテストの接続先を渡せるようにした（既定は MX Stage の値）。
  - `demo`: 予約の ID・ホストの判定だけ写した（`isReservedDemoHost`・`demoLangOfConnectionId`・`demoLangOfBaseUrl`）。MX Stage の `src/shared/demo.ts` はここから出し直すので、決まりは 1 か所。
  - `node/*`: 保存の場所は既定 `stateDir()`（~/.config/mxstage）。keychain の service・account、DPAPI の entropy、予約の決まりを引数で上書きできる（既定は MX Stage の今の値）。
    上書きする名前は OS の道具に渡す文に埋め込むので、英数字・空白・`.`・`_`・`-` の 64 文字までに限った。
  - `node/writeGuard` と `handleMaximoProxy` の `writeGuard`: 本番の接続先への書き込み（POST）で `LicenseStore.authorize` を必ず通す守り。
    既定は切ってある（MX Stage の振る舞いは変えない）。オンにすると、環境を言わない接続先は本番として扱い、申告が無い（null）接続先には書かせない。
- 言葉の設定は 1 つ（`setLocale`・`getLocale` は本体の出口。`/license` の文言も同じ設定を読む。`scripts/check-exports.mjs` で確かめる）。
- 中間形（`/eam`）: 型（資産の木・保全計画・作業の手順・作業の実績）と Maximo の対応（MXAPIASSET・MXAPIOPERLOC、MXAPIPM・MXAPIJOBPLAN、MXAPIWODETAIL）、読む関数まで。
  id は `種類:サイト/番号`。資産の親は PARENT、無ければ設置場所。場所の親は LOCHIERARCHY（systemId を渡せばその階層）。輪になった節・親が木に無い節は根にする。

前から落ちている 3 件は、どれもこの PC（Linux）の事情で、差し替えとは関わらない:

- `tests/bridge/static.test.ts`「配信ディレクトリの外は解決しない」: Windows のドライブ（`/C:/windows`）を Linux では普通の名前として解決する。
- `tests/dev/demo-files.test.ts`「目録の SHA-256 が製品に埋め込んだ値と同じ」: この PC で作ったデモのデータの SHA-256 が、埋め込んだ値と違う。
- `tests/setup/setup-local.test.mjs`「resolveBridgeEntry」: Windows の区切り（`\`）を Linux の `path.join` で比べている。

## 自分で決めたこと

- MX Stage の試験は、部品に写したうえで MX Stage にも残した（差し替えの前と後で同じ 1,414 件が通ることを示すため）。重なる試験は、部品が npm に出たあとで MX Stage から消してよい。
- 部品は束ねずに tsc でファイルごとに出す（入口が別でも、言葉の設定などのモジュールを 1 つに保つため）。
- MX Stage の `THIRD_PARTY_LICENSES.txt`（.mcpb・npm に入る）に、部品が自分の LICENSE（BUSL）と共に載る。同じ Licensor の物だが、載せたままにした（外すなら build-mcpb.ts で @mxstage/* を除く）。
- `.npmrc` に `legacy-peer-deps=true`（MX Stage と同じ。npm 10 が vitest の peer で止まるため）。
